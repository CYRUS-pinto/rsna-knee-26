### What external data is inside the public 0.956/0.957 blends (for the disclosure ask in 743416)

Chris Carr's post in 743416 asks everyone to list the external datasets they used. I went back through the notebooks I'd been forking to check what's actually in them, and it wasn't obvious from the titles. Most of the top public blends are built from the same handful of models, so I figured a table might save people some digging.

All of this comes from the authors' own notebooks, write-ups and the manifest.json files in their datasets. I'm reading code and manifests, not training logs, so if an author says otherwise, go with the author.

|Model|Dataset|External data in training|
|---|---|---|
|nartaa CoAtNet 384 (`..._oai_d96_r384_swa.pt`)|nartaa/rsna-knee-publication-swa-weights-20261007|OAI, 2,399 knees, used only for PF OA, Lateral OA and Synovitis (see nartaa's write-up in 746792)|
|nartaa CoAtNet 224 crop (`..._oai_d96_c08_r224_swa.pt`)|same dataset|OAI, same recipe|
|heliosli R7 ConvNeXt-S (bundle 8c7b666e)|heliosli/rsna-knee-compact-r7cnxfsss|fastMRI images with fastMRI+ boxes as an auxiliary task (`fm_aux`, weight 0.3 in the manifest; heliosli's notebook also says so)|
|heliosli R6 ConvNeXt-S (bundle fe055406)|used by the new "0.9576" notebook|no `fm_aux` entry in its manifest|
|heliosli S6 (compact-v1)|heliosli/rsna-knee-compact-v1|nothing external I could find|
|dreaddevelopment Raptor CoAtNet|dreaddevelopment/raptor-knee-maxspan|nothing external I could find|
|`anatomy.pt` (places the crops for R6, R7 and S6)|heliosli/rsna-orthofoundation-fold0-epoch7-20261004|SKM-TEA|

All the ConvNeXt/CoAtNet models start from ImageNet weights through timm, which I'm not counting.

A few things that tripped me up:

1. The orthofoundation dataset name is misleading. The R6/R7/S6 notebooks attach it for the code and for `anatomy.pt`. From what I can see they don't load the OrthoFoundation ViT weights in it, which are the OAI-pretrained part. If you blend heliosli's ViT-L itself, that one is OAI-derived.
2. `heliosli/rsna-knee-r6-frozen-fe055406` currently holds the R7 bundle, not R6, despite the name (its manifest hash matches R7's). The "0.9576" notebook needs an older version of it. If you fork either one, check that the BUNDLE_ID in the notebook matches what's mounted.
3. If you forked any of the 0.956/0.957 R7 + Raptor notebooks, you're almost certainly using OAI (through nartaa) and fastMRI (through R7), plus SKM-TEA through `anatomy.pt`. All three are free with registration and a click-through agreement, which is the kind of access Chris said is fine. But per that same post they still need to be listed.

Not covered: hengck23's MaViT (training data not stated), the DINOv2 / A5 / RadImageNet bundles, and goodpjw's reader (the "read the report then the knee" notebook uses frozen fastMRI+ ViTDet heads, so add fastMRI+ if you use that one).

Corrections welcome, especially from the model authors.

Yes working with image vs report is the objective, one of the experiments lately:

- Read every report several independent times.
- Fuse the readers into one probability per cell. Combine the per-reader probabilities into a single fused probability per (study, finding) cell — use a weighted mean over the reader pool. Keep, per cell: the fused probability, the number of readers that answered (__nsrc), their disagreement (__spread = max−min), and a confidence (__conf).
- Find the cells most likely to be wrong.
- Re-read the actual report text per cell.
- Apply verdicts onto the fused table.
- Fill the silent cells with measured priors, not zero.
